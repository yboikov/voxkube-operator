# AGENTS.md: working on voxkube-operator

Read this before changing anything. It is loaded automatically by Google Antigravity, Claude Code, Cursor and
other agents that support `AGENTS.md`.

## What this is

A Kubernetes/OpenShift operator (Go, controller-runtime, kubebuilder markers) that runs OpenVox (open-source
Puppet 8): CA, compilers, OpenVox DB (PuppetDB), the Hiera Secret Bridge, the ENC and Prometheus discovery.
API group `voxkube.io/v1alpha1`, with kinds `VoxCluster`, `VoxNode` and `VoxDiscovery`.

**The source of truth for behaviour is the "API Reference" section of `README.md`.** It documents every field,
default, status value, created resource and HTTP call as actually implemented. When you change behaviour,
update that section in the same change. Never document a field as working unless a controller reads it.

## Project history (so you don't redo or undo work)

- The initial version was generated by Google Antigravity. A review (PR #1) found many CRD fields that no
  controller read, and documented the real behaviour.
- PR #2 (`fix/v1alpha1-gaps`) implemented those gaps: PKI renewal and SANs, CRL sync, autosign modes,
  VoxNode auto-creation, external/CNPG database credentials, PuppetDB integration on compilers (termini,
  `puppetdb.conf`, `routes.yaml`), ENC modes, report processors, g10k config/auth, synchronized rollout vs
  sidecar, PVC/imageVolume code, HPA, honest status phases and conditions, VoxNode PuppetDB status, and PQL
  discovery.
- Deliberate design decisions. Keep them unless the owner says otherwise:
  - `database.postgres.mode: builtin` is **ephemeral and for dev/demo only**. Production uses `external`
    (CloudNativePG). Do not add persistence to builtin.
  - The CA Secret `<cluster>-ca-tls` and PVC `<cluster>-ca-data` are **not owned** by the VoxCluster, so the CA
    survives deletion. Do not add owner references to them.
  - Only the certificate in `<cluster>-ca-tls` (CA endpoint + operator client) carries `pp_cli_auth`, encoded as
    UTF8String. Never put it on other leaf certs (compilers, DB, Prometheus scraper).
  - `<cluster>-ca-tls` holds the CA key and is mounted **only** into the CA pod. Compilers mount
    `<cluster>-server-tls` and OpenVox DB `<cluster>-db-tls` (own leaf cert, `ca.crt`, `crl.pem`; never `ca.key`),
    built by `reconcileWorkloadTLS`. OpenVox DB only accepts certificates in its `certificate-allowlist`.
  - The ENC parameter `noop` from `globalNoop` is advisory; Puppet code must honour it.
  - `puppetserver.conf` keeps the `master-*` key names that are known to work with the shipped image.
  - `spec.networking` has two symmetric blocks, `server` (compilers) and `ca`; each feeds the SANs of its own
    certificate. Add new exposure options to `EndpointNetworkingSpec`, not as flat fields.
  - `VoxDiscovery` publishes targets only as EndpointSlices, so its ServiceMonitor must keep
    `serviceDiscoveryRole: EndpointSlice`. Per-target labels (`endpointLabels`, VoxNode
    `monitoring.voxkube.io/<label>`) are **EndpointSlice labels**: machines are grouped into slices by label set.
    Do not put them in endpoints' `deprecatedTopology`: the API server silently drops that field in
    `discovery.k8s.io/v1` (this shipped broken in 0.2.2).
  - `deploy.sh` (g10k) must fail loudly rather than "succeed" with no code: it exits non-zero when
    `git ls-remote` fails, the remote has no branches, or g10k leaves `environments/` empty (then it also deletes
    the g10k cache, whose broken mirror would otherwise keep every later run empty). g10k itself exits 0 in
    those cases. A pod once ran for hours without code because of this (fixed in 0.2.6).
  - The VoxNode finalizer is released only after the CA clean and OpenVox DB deactivation succeeded (each step is
    recorded in `status.caCleaned` / `puppetDBDeactivated` and not repeated). The only ways around it are a
    missing or deleting VoxCluster and the annotation `voxkube.io/skip-cleanup: "true"`. Don't go back to
    "log and proceed": it leaves certificates valid on the CA for machines that are gone.
  - Unstructured objects the operator owns (Routes, cert-manager Certificates, ServiceMonitors) are updated only
    when the hash of what it renders (`voxkube.io/applied-hash`) changes, through `prepareUnstructuredUpdate`,
    which also keeps a router-generated Route `spec.host` and foreign annotations. Use it for new unstructured
    kinds instead of a blind Update.
  - Switching a component off deletes its objects (`pruneDisabledComponents`), but only objects controlled by
    the VoxCluster, and never the CA PVC or CA Secret.
  - The OpenVox DB plain-HTTP listener is bound to 127.0.0.1 and only serves the exec readiness probe. Never
    expose it on the Service: it is unauthenticated.
  - The `voxkube_node_*` metric label set is fixed per process (`--node-metric-labels`). Don't derive label names
    from whatever labels the VoxNodes carry: that changes the identity of every series when one node is labelled.
  - Controllers react only to changes that matter to them (`predicates.go`): never let a status write re-trigger
    its own controller or fan out (a VoxNode check-in must not re-run the VoxCluster stack; VoxDiscovery's
    `lastSyncTime` must not trigger the next sync). Diff before every write (`Update`, `Status().Update`).
  - The VoxCluster controller is the only writer of `<cluster>-enc-nodes` and `<cluster>-hiera-secrets`. It renders
    them first in `reconcileStack`, so VoxNode changes apply even while later steps fail. VoxNodes don't write them.
  - CA and OpenVox DB mTLS clients come from `mtlsClients` (one per VoxCluster, rebuilt on credential change).
  - A (cluster, certname) is owned by its oldest VoxNode (`certnameOwner`, `servedVoxNodes`). Duplicates never
    sign, revoke, clean or classify, and are deleted without cleanup. `*.svc` certnames are reserved
    (`reservedCertname`): OpenVox DB's allowlist trusts the service certname.
  - Secrets are never cached (`DisableFor` in `cmd/main.go`). Watch them with `builder.OnlyMetadata`, list them with a
    label selector (`client.MatchingLabels`), and keep Secret mappers selective (`clustersForSecret`): a Secret
    watch must never enqueue on unrelated Secrets such as Helm releases.
  - Generated object names derived from certnames keep the whole FQDN (`dnsLabel`, `certManagerDefaultName`);
    never cut at the first dot (two machines can share a short hostname).
  - Required-field combinations are CEL rules on the CRD types (`+kubebuilder:validation:XValidation`). Keep
    controllers tolerant anyway (older objects predate the rules).
  - `code.git.branches` must be applied identically in three places: the operator poll (`SelectBranches`), g10k
    (`filter_regex`, matched against the bare branch name) and `deploy.sh` (`git ls-remote` with `refs/heads/<b>`).
    With no branches, `RefsHash` must stay byte-for-byte what it was, so upgrades don't roll the compilers.
  - JVM pods (CA, compilers, OpenVox DB) get readiness, startup and liveness probes via `withProbes`: keep the
    liveness grace (≥ 2 min) and startup budget (≥ 5 min) generous; a restarted compiler costs more than a slow one.
  - Every VoxCluster pod spec goes through `applyPlacement`. PodDisruptionBudgets (`reconcilePDB`) exist only for
    components with two or more replicas; never create one for a single replica (it blocks node drains).
  - The external ENC (`enc.sh`, `externalHttp`) falls back to the default only on HTTP 404. Any other failure
    exits non-zero so the catalog request fails, rather than compiling the wrong classification.

## Rules

1. After changing anything in `api/`, run `make generate manifests`. CI fails if the generated deepcopy code or the
   CRDs (in both `config/crd/bases` and `charts/voxkube-operator/crds`) are out of date.
2. Run `go test ./...` and `helm lint charts/voxkube-operator` before committing. Add a test for every behaviour
   change (the tests use the controller-runtime fake client plus `httptest` mocks for the CA and PuppetDB).
3. Every workload must stay OpenShift `restricted-v2` compatible: no hard-coded UIDs/GIDs/fsGroup, run as
   non-root, drop all capabilities, use `RuntimeDefault` seccomp. Use `buildOpenShiftPodSecurityContext` and
   `buildRestrictedContainerSecurityContext`.
4. Files mounted with `subPath` don't update in place. Put their content into the `voxkube.io/config-hash` pod
   annotation so changes roll the pods.
5. Never put secrets in ConfigMaps (e.g. `database.ini` lives in a Secret).
6. The owner's environment does not allow Docker Hub at runtime and uses only Rocky/Ubuntu/RHEL hosts.
   Images are built for `linux/amd64` only (arm64 was dropped on purpose). Prefer
   `registry.access.redhat.com`, `quay.io` or `ghcr.io` images. (The build stages still use `docker.io/library/golang`,
   a known item to replace.)
7. Keep `README.md` → "API Reference" accurate (see above), including the "Known limitations" list.
8. OpenVox versions are pinned (README → "Image versions"). To change them, update **all** of: the `ARG ..._VERSION`
   lines in `images/openvox-*/Containerfile`, `internal/controller/versions.go`, the chart's `values.yaml` and
   `templates/voxcluster.yaml`, and the README examples. Renovate does this automatically. Never go back to
   unversioned `dnf install openvox-server` or `:latest` defaults, and stay on 8.x unless the owner decides to
   move to OpenVox 9 (which needs the `openvox9` repo and has breaking changes).
9. Operator releases follow SemVer (README → "Versioning & Releases"). Add user-visible changes to the
   `[Unreleased]` section of `CHANGELOG.md` in the same PR. Only the owner tags releases; a release PR bumps
   `version` and `appVersion` in `Chart.yaml` together (a test enforces that they are equal).
10. CI publishes images only for `v*` tags (releases and pre-releases) and from the weekly OpenVox rebuild;
    pushes to `main` run lint and tests only. Don't add image pushes to `main` builds.

## Known limitations / backlog

- Importing an existing Puppet CA (migration from Foreman/puppetserver) isn't supported; CA rotation is manual.
- Compilers rely on Jetty's CRL reload for `crl.pem` updates.
- ServiceMonitor TLS needs exporter certificates with IP SANs (Prometheus scrapes by IP).
- `sslMode: verify-*` for external PostgreSQL needs the DB CA in the OpenVox DB JVM trust store; there's no
  field for it yet.
- Build stages pull `golang` from Docker Hub.
- **Scaling limits (README → "Scaling limits"); fix these before an installation grows past ~100 machines with
  certificates:**
  - `<cluster>-hiera-secrets` is a single Secret holding all node, role and common Hiera data, including
    cert-manager certificates (≈5–7 KB each), so it hits the 1 MiB Secret limit at roughly 100–150 machines with a
    certificate each. Fix: one Secret per node (`<cluster>-hiera-node-<hash of certname>`) and per role, mounted
    into the compilers through a projected volume (or rendered into a single emptyDir by an init/sidecar), keeping
    the `nodes_<certname>.yaml` / `roles_<role>.yaml` / `common.yaml` file names so `hiera.yaml` doesn't change.
    Watch the pod spec size: a projected volume with hundreds of sources is fine, thousands are not.
  - Every VoxNode reconcile calls the cluster-wide ENC/Hiera refresh, so total work per 5 minutes is O(N²). Fix:
    move rendering to one debounced, cluster-level step triggered by VoxNode/Secret changes (e.g. enqueue the
    VoxCluster and render there), and keep VoxNode reconciles to CA/OpenVox DB status only.
